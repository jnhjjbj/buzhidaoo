信息收集分两路：**被动**是只用公开数据，不碰目标；**主动**是直接对目标发包。前者隐蔽，后者准确，实战里通常先被动圈定范围，再用主动验证。

> 以下所有操作都在课程提供的授权靶机环境内完成，请勿对未授权目标扫描。

## 一、被动扫描：先不惊动对方

被动方式包括搜索引擎、证书透明度日志、空间测绘引擎、DNS 历史记录等。课程里主要用 ZoomEye。

```text
# 空间测绘常见语法
app:"nginx"                 # 按组件
port:"3389" country:"CN"    # 按端口 + 国家
ip:"192.168.0.0/24"         # 按网段
title:"后台管理"             # 按页面标题
```

关键思路是**从外到内收敛**：

1. 用组织名 / 域名 / 备案号找资产
2. 用 IP 段和证书关联找旁站
3. 记录开放端口与指纹，形成资产表

被动收集的短板很明显：数据有延迟，可能滞后几个月；内网资产基本查不到。

## 二、主动扫描：拿真实状态

nmap 是主力。先做主机发现，再做端口与服务识别。

```bash
# 主机发现（不扫端口，只判断存活）
nmap -sn 192.168.10.0/24

# 常用组合：SYN 扫描 + 版本探测 + 默认脚本 + 跳过 ping
nmap -sS -sV -sC -Pn -T4 192.168.10.20 -oN scan.txt

# 全端口，速度慢但不会漏
nmap -sS -p- --min-rate 2000 -Pn 192.168.10.20
```

常用的几组参数含义：

| 参数 | 作用 | 备注 |
| --- | --- | --- |
| `-sS` | SYN 半连接扫描 | 需要 root，快且不易留日志 |
| `-sT` | 全连接扫描 | 无权限时用，慢 |
| `-sV` | 服务版本识别 | 靠特征匹配，可能误报 |
| `-sU` | UDP 扫描 | 覆盖 DNS/SNMP 等 |
| `-Pn` | 跳过存活检测 | 目标禁 ping 时必须加 |
| `-T4` | 提高并发 | 内网可用，公网别乱调 |

## 三、两种方式的结果对比

同一台靶机：

| 项目 | 被动（ZoomEye） | 主动（nmap） |
| --- | --- | --- |
| 开放端口 | 只显示 80 / 443 | 22、80、3306、8080 |
| 服务版本 | 由指纹推测，较粗 | 精确到小版本 |
| 时效性 | 历史快照，可能过期 | 当前实时状态 |
| 被发现的可能 | 不产生流量 | 目标防火墙/IDS 有记录 |

结论：被动负责**广度**，主动负责**深度**，两者互补，不要只做一边。

## 四、踩过的坑

1. **`-sn` 扫不到主机**：Windows 默认拦 ICMP，换 ARP 扫描（`-PR`，仅同网段有效）。
2. **端口显示 filtered**：说明被防火墙丢弃而不是关闭，`-Pn` 配合 `--reason` 看具体原因。
3. **`-sV` 卡住**：加 `--version-light` 降低探测强度，或 `--host-timeout 300s`。
4. **速度太快把靶机打挂**：`-T4` 在脆弱服务上已经偏激进，教学环境用 `-T3` 更稳。

## 五、小结

扫描不是目的，形成资产视图才是。建议每次都把结果落到一张表里：`IP / 端口 / 服务 / 版本 / 备注`，后面写报告和找突破口都靠它。
